## 核对方法

公式对不对不该靠读，该靠算。全部结论来自**两个互相独立的数值方法**：

| 方法 | 用途 | 可信度验证 |
|---|---|---|
| 解析级数解 | Swerling 1 + N 脉冲非相干积累的精确 Pd | 与 N=1 闭式解 `Pfa^(1/(1+SNR))` 吻合到 1e-4 |
| 蒙特卡洛（30 万次） | 独立的 Pd 交叉验证 | 与级数解吻合到 0.0012 |

两个方法在 7 组参数上互证一致，所以下面引用的"真值"是可以信的。

## P0-1：Step 4「版本二」与附录 A.3 代码把 (4π) 乘了两遍

规格书 Step 4 给了两条式子。**版本一（标准式）是对的，版本二（"简化等价格式"）是错的**，而附录 A.3 的参考代码用的是版本二。

```
版本一（对）：
  Pr = Pt·G²·λ²·σ / ( (4π)³ · R⁴ · L_sys² )

版本二（错）：
  L_twoway_linear = 10^(2·FlushStub/10) = (4πR/λ)⁴
  Pr = Pt·G²·σ·λ² / ( 1984.4 · L_twoway_linear · L_sys² )
                       ↑ 这个 1984.4 = (4π)³ 不该在这里
```

实测（9.4 GHz，100 km，5 m²，Pt=1 MW，G=33 dBi）：

```
版本一 Pr = 1.617060e-14 W
版本二 Pr = 6.709010e-25 W
比值      = 4.148894e-11  →  -103.82 dB
理论比值 (λ/4π)⁴          = 4.148890e-11
```

**根因**：`L_twoway_linear` 已经是完整的 `(4πR/λ)⁴`，其中包含了 `(4π)⁴` 与 `1/λ⁴`。分母里再除以 `(4π)³`，等于多乘 `(λ/4π)⁴`。

**后果**：SNR 低估 103.8 dB，等效最大探测距离**缩短 394 倍**。一台本该 100 km 发现目标的雷达，会变成 0.25 km。

**修正**：直接采用版本一，**删掉版本二**。若确实想用 `L_twoway` 表示，正确的形式是

```
Pr = 4π · Pt · G² · σ / ( λ² · L_twoway_linear · L_sys² )
```

（脚本已验证此式与版本一比值恒等于 1。）

## P0-2：Step 3f 欺骗干扰路径永远算不出结果

```
规格书 3f②：
jammerRcvPower = powerWatts × G_radar_toward_jammer × G_jammer_toward_radar
               × λ² / ( (4π)² × R² × L_oneway_linear )
                                        ↑ 这一项是多余的
```

`L_oneway_linear = (4πR/λ)²`。Friis 式里 `(4πR)²` 已经体现了扩散损耗，再除一次 `L_oneway` 等于把路损算了两遍。实测：

```
规格书写法 Pr = 1.651703e-18 W
Friis 标准 Pr = 2.564283e-03 W
比值 = 6.441188e-16  →  -151.9 dB
理论多除的因子 (λ/4πR)² = 6.441188e-16
```

**后果不是精度问题，而是功能失效**：

```
正确的干扰机 SNR  =  118.1 dB  →  P_deception = 0.9
规格书的干扰机 SNR =  -33.8 dB  →  P_deception = 0.0
```

`P_deception` 恒为 0，`falseTargetCount` 恒为 0——**RGPO/VGPO 一次都不会生效**。这个 bug 很难在集成测试里发现，因为"没有假目标"看起来像正常结果。

**修正**：删掉 `÷ L_oneway_linear`。`L_oneway_dB` 若要保留，只能用于日志/报出，不能进分母。

## P0-3：3f 里的 `powerWatts` 指雷达还是干扰机

3f 段落物理含义是"干扰机收到**雷达**信号"，所以 `powerWatts` 应是雷达发射功率。但 2.2 节定义 `powerWatts` 是**干扰机**发射功率。

同名同字段两种含义，是实现在最容易静默写错的一类问题——写错了两个方向都"看起来能跑"，只是数值差几十 dB。

**修正**：把 3f 里的改名为 `radarPowerWatts`，与 `jammerPowerWatts` 区分。

## P1-4：pdCurve 只生成一次，但脉冲数依赖步长

规格书 Step 7 写"初始化时生成一次"，可固定指向模式下：

```
pulsesPerDwell = stepDuration × prf
```

而 `stepDuration` 是想定的运行期参数（1~60 s）。实测（prf = 1000 Hz）：

| stepDuration | N_pulses | 积累增益 |
|---|---|---|
| 1 s | 1,000 | 30.0 dB |
| 2 s | 2,000 | 33.0 dB |
| 10 s | 10,000 | 40.0 dB |
| 60 s | 60,000 | 47.8 dB |

1 s 与 60 s 相差 **17.8 dB**，但表只生成一次 → 换了步长就用错了脉冲数。

同样的问题在旋转扫描模式下不出现（`dwellTime` 与步长无关），所以这个 bug 只在固定指向 / 电子扫描模式下暴露，**更容易漏测**。

**修正**：pdCurve 的缓存键必须是 `(mode, N_pulses)`，而不是只有 `mode`。

## P1-5：N_encounters 的 `round` + `max(1,…)` 高估探测机会

规格书：`int N = inCoverage ? max(1, round(N_scans)) : 0`

| stepDuration | scanRate | 理论次数 | 规格书取 | 放大 |
|---|---|---|---|---|
| 1 s | 6 rpm | 0.10 | 1 | **10×** |
| 1 s | 15 rpm | 0.25 | 1 | **4×** |
| 2 s | 6 rpm | 0.20 | 1 | **5×** |
| 1 s | 30 rpm | 0.50 | 1 | 2× |

只要一次步长内转不满一圈，理论值就 < 1，被 `max(1,·)` 抬到 1。

**修正**：向下取整得 k 次确定相遇，余下的小数部分按旋转初相做一次**概率抽取**（`rng < frac` 则 +1 次）；或干脆把旋转相位作为实体状态在步之间传递——后者更对，因为相位连续时"这次没扫到、下次一定扫到"才是物理的。

## P1-6：ListStub 的方位角越界会抛异常

`A.1 ListStub` 第一行：`if (a > 180.0) throw std::runtime_error(...)`

但规格书 3c 的算法是 `offset_jam = |jammer.beamAzimuth - jammerToRadarBearing|`。两个角各自在 `[0,360)`，差值范围是 `[0,360)`——**不是 `[0,180]`**。实测：

```
beamAzimuth= 10°  目标方位=350°  offset=340°  → 抛异常
beamAzimuth=350°  目标方位= 10°  offset=340°  → 抛异常
```

只要干扰机天线大致背对雷达就**崩溃**。同一个问题在 `offset_radar` 上也存在。

**修正**：

```cpp
static double WrapOffset(double a, double b) {
    return std::abs(std::fmod(std::fmod(a - b + 540.0, 360.0) + 360.0, 360.0) - 180.0);
}
```

## P1-7：退化输入无保护

`FlushStub` 里有两处 `log10` 与一处除法，都没有下限保护：

| 输入 | Python | C++（真实运行环境） |
|---|---|---|
| `dist_km = 0` | 抛 `ValueError` | `std::log10(0)` 返回 `-inf`，**不抛** |
| `freq = 0` | 抛 `ValueError` | 返回 `-inf`，**不抛** |
| `pulseWidth = 0` | — | `bw_hz = 1/(0×1e-6)` **除零** |

**C++ 不抛异常才是危险的地方**。距离 0 → `L = -inf` → `L_twoway = 0` → `Pr = x/0` → `SNR = ±inf` → `round(SNR_dB + 20)` 把**负无穷转 int 是未定义行为**。实测常见表现是得到一个 `INT_MIN` 量级的负数，`clamp` 后查到 `idx = 0`，于是"距离 0"这个明显该报错的输入静默变成了"Pd = 表头值"。

**修正**：参数入口做下限校验（距离下限、`pulseWidth > 0`、`frequency > 0`），并把 `FlushStub` 内的 `log10(x)` 换成 `log10(max(x, eps))` 作为第二道防线。

## P2-8：波束形状损耗 1.6 dB 没标方向口径

规格书 Step 2：`G_target = antennaGain_dBi - 1.6`

对 sinc² 方向图实测：

```
±BW/2 内单程增益的 dB 均值   = -0.974 dB
±BW/2 内单程增益的线性均值   = -0.888 dB
按双向折算（×2）             = -1.948 dB
```

1.6 这个数本身不离谱（Blake 表格给 1.6 dB）。**问题在于方向没标**：

| 理解 | Pr 上实际扣除 |
|---|---|
| 1.6 dB 是「单向增益损耗」 | 3.2 dB（因为 G 在雷达方程里平方进入） |
| 1.6 dB 是「双向功率损耗」 | 1.6 dB（即 G 上只该扣 0.8 dB） |

两种理解相差 1.6 dB → 探测距离相差 **+9.6%**。

**修正**：二选一并写明。若沿用 Blake 的 1.6 dB，应写成 `Pr /= 10^(1.6/10)`，而不是从 `G_target` 上扣。

**附注**：AFSIM 本身并不用这个经验系数——它按每个时刻的实际波束偏离角查方向图。如果大步长实现里能拿到偏离角，用 `ListStub` 更准；1.6 dB 只适合"几何冻结"这条近似路径。

## P2-9：G_peak 推导公式的单位

规格书 7.2：`G_peak_dBi = 10·log₁₀( 4π / ( 2·sin(HBW/2) × VBW ) )`

| HBW×VBW | 规格书表值 | 按弧度算 | 按度数直算 |
|---|---|---|---|
| 1°×3° | 40 dBi | 41.4 | **6.4** |
| 2°×10° | 33 dBi | 33.1 | **-1.3** |
| 5°×20° | 27 dBi | 26.2 | **-2.8** |

只有把两个角都换算成**弧度**才对得上表值。照字面（用度数数值）实现会得到荒谬的负增益。

**修正**：写成 `4π/(θ_H·θ_V)`，θ 为弧度；`sin` 修正只在波束很宽（>10°）时才需要。

## P2-10：表 7.4 的 N>1 各列在低 SNR 段系统性偏低

用两个独立方法算出的 Swerling 1 真值（Pfa = 1e-6）：

| SNR(dB) | N=1 表/真 | N=10 表/真 | N=56 表/真 | N=100 表/真 |
|---|---|---|---|---|
| 0 | 0.001 / 0.001 | 0.002 / **0.121** | 0.010 / **0.466** | 0.030 / **0.578** |
| 5 | 0.040 / 0.036 | 0.120 / **0.486** | 0.350 / **0.782** | 0.550 / **0.839** |
| 10 | 0.290 / 0.285 | 0.620 / **0.791** | 0.870 / **0.925** | 0.940 / 0.946 |
| 13 | 0.520 / 0.517 | 0.820 / **0.889** | 0.950 / 0.961 | 0.980 / 0.972 |
| 15 | 0.660 / 0.655 | 0.900 / 0.928 | 0.980 / 0.975 | 0.995 / 0.982 |
| 20 | 0.870 / 0.872 | 0.980 / 0.977 | 1.000 / 0.992 | 1.000 / 0.994 |

- **N=1 一列完全正确**（与 Swerling 1 单脉冲闭式解 `Pfa^(1/(1+SNR))` 逐格吻合）。
- **N>1 各列在低 SNR 段偏低**：N=10、SNR=0 dB 处表值 0.002，真值 0.121——**差 60 倍**。最大偏差 0.548（SNR=0 dB, N=100）。
- 高 SNR 段（≥13 dB）两者接近，说明表格是按高 SNR 锚点标定的。

**物理原因**：低 SNR 下，起伏目标偶发的强回波贡献了大部分检测概率。离散化或粗略近似把这条"长尾"抹平了，而它恰恰是 Swerling 1 行为的主体。

**修正**：pdCurve 直接用下面的精确级数生成，参考表只当量级校对，不能当验收基准。

### 可直接使用的精确 Pd（替换 Kanter 近似）

```
设 V 为门限：  Pfa = e^{-u} · Σ_{k<N} u^k/k! ，u = V/2
设 NS = N · SNR_linear，β = NS/(1+NS)
则
  Pd = e^{-u} / (1+NS) · Σ_j  β^j · Σ_{k<N+j} u^k/k!
```

内层 χ² 尾和随 j 只增加一项，**必须增量累加**（每个 j 重算一遍是 O(j²)，实测几分钟都跑不出结果）。

已实测与蒙特卡洛吻合到 0.0012，且与教科书 Swerling 1 曲线一致：

- N=1, Pd=0.9 → ~22 dB（教科书约 21 dB）
- N=10, Pd=0.9 → ~13.5 dB（教科书约 13 dB）
- N=10, Pd=0.5 → ~5.2 dB（教科书约 6 dB）

也可以用离线预先算好 61 点表——只要生成公式换成上面这个。

另外：`N_pulses = 56` 这种数值从哪来需要说明（`dwellTime × prf` 通常是小数），规格书按 `round` 还是插值处理，要写明。

## P2-11：脉冲干扰没有乘占空比

规格书 3b：`jamType = 1（SyncPulse）/ 2（ChaoticPulse）` 时 `bwMatch = 1.0`。

但脉冲干扰只在占空比 d 的时间内有功率输出，进入雷达的平均功率应为 `P × d`：

| 占空比 | 有效功率应低 |
|---|---|
| 100% | 0 dB |
| 10% | 10 dB |
| 1% | **20 dB** |

一个 1% 占空比的脉冲干扰机，压制效果被高估 20 dB。

**修正**：`bwMatch` 之外再乘占空比，或把占空比并入干扰机的平均功率参数。SyncPulse 情况特殊（只对准雷达接收窗发射），可以论证不乘，但**要写明是有意为之**。

## P2-12：步长内几何冻结的量化代价

规格书 Step 1 写"步长内几何变化可忽略"。实测在 R = 50 km 处：

| 步长 | 目标速度 | 步内位移 | R⁻⁴ 变化 |
|---|---|---|---|
| 1 s | 300 m/s | 0.3 km | -0.10 dB |
| 10 s | 300 m/s | 3.0 km | -1.01 dB |
| 30 s | 300 m/s | 9.0 km | -2.88 dB |
| 60 s | 300 m/s | 18.0 km | **-5.34 dB** |
| 60 s | 900 m/s | 54.0 km | **-12.72 dB** |

**这个误差比"波束形状损耗到底该 1.6 还是 0.8 dB"的争论量级大得多**，也是"大步长"这个前提本身要承担的代价。

**修正**：给出适用边界（例如"60 s 步长只用于速度 < 100 m/s 的目标"），或在步内做 2~3 段分段计算。若要做后者，注意分段之间要保持随机流的连续性，否则会破坏可复现性。

## 规格书里**做对了**的部分（不要动）

避免过度修正，这几处经核算是对的：

1. **`FlushStub` 的常数**：`K = 1.7570265424158548e-09` 精确等于 `(4π·1000/c)²`，即"距离用 km 的单程自由空间损耗"。与 `20log10(4πRf/c)` 偏差 2.8e-14 dB。
2. **Step 4 版本一（标准雷达方程）**：`/((4π)³·R⁴·L²)` 形式正确（`64π³ = (4π)³ = 1984.4`）。
3. **带宽处理**：`bw_hz = 1/pulseWidth` 配合 `N = kTB`，等价于匹配滤波输出 SNR `E/N₀`——**没有漏掉脉压增益**，这一点很多人会搞错。
4. **`dwellTime = horzBeamWidth / (6 × scanRate)`**：角速度 `6·scanRate` °/s 推导正确。
5. **连续波干扰的 `bwMatch = (overlap)/(jammer.bandwidth)`**：当干扰带宽大于雷达带宽时等于 `B_r/B_j`，与"干扰机把功率均匀摊在自己带宽上"的物理图像一致。
6. **pdCurve 降到 1 维的思路**：固定 `(Pfa, Case, N)` 后只随 SNR 变化，这个降维判断是对的（只需修缓存键）。
7. **N_encounters 的覆盖判断**（全向 / 扇区 / 固定指向三分支）：物理分类正确。
8. **输出 `vector<ScanResult>` 而非聚合布尔值**：交给上层做 M/N 逻辑，这个设计是对的，也正是"大步长"能成立的关键。

## 验收锚点

用修正后的公式跑一条完整链路（Pt = 1 MW，G = 33 dBi，σ = 5 m²，f = 9.4 GHz，τ = 1 μs，prf = 1000 Hz，HBW = 2°，scanRate = 15 rpm，L_sys = 4 dB）：

```
dwell = HBW/(6·scanRate) = 22.22 ms → N_pulses = 22
噪声 N = kTB = 1.0907e-14 W

  距离    SNR/脉冲    Pd(峰值增益)   Pd(扫描均值)
 25 km    25.8 dB        0.996          0.995
 50 km    13.8 dB        0.943          0.918
100 km     1.7 dB        0.403          0.275
150 km    -5.3 dB        0.020          0.005
200 km   -10.3 dB        0.000          0.000

单次扫描 Pd=0.5 的距离 ≈ 85 km
```

实现出来如果偏离这个锚点几十公里以上，说明某处单位或系数错了，而不是"雷达性能就这样"。

注意这是**单次扫描**的严格口径；实际雷达用 M/N 建航，等效作用距离更大。

## B. 1 s 下 `max(1, round(…))` 的真实后果：把所有 < 90 rpm 的雷达钳到 60 rpm

| scanRate (rpm) | `N_scans` | 规格书取 | 真实相遇/分 | 规格书相遇/分 | 放大 |
|---|---|---|---|---|---|
| 6 | 0.100 | 1 | 6 | 60 | **10×** |
| 10 | 0.167 | 1 | 10 | 60 | 6× |
| 12 | 0.200 | 1 | 12 | 60 | 5× |
| 15 | 0.250 | 1 | 15 | 60 | 4× |
| 24 | 0.400 | 1 | 24 | 60 | 2.5× |
| 30 | 0.500 | 1 | 30 | 60 | 2× |
| 45 | 0.750 | 1 | 45 | 60 | 1.33× |
| 60 | 1.000 | 1 | 60 | 60 | 1× |
| 90 | 1.500 | 2 | 90 | 120 | 1.33× |
| 120 | 2.000 | 2 | 120 | 120 | 1× |

**§一 那句「1 秒步长：每秒调用一次 → 该秒内的扫描可逐个模拟」只有 `scanRate ≥ 60 rpm` 才成立。**
常见搜索雷达是 6~15 rpm，1 s 内 `N_scans = 0.1~0.25`——不是"逐个模拟"，而是"十次里有一次扫到"。
把 1 s 的相遇钳成 1，等价于**把所有转速低于 90 rpm 的雷达都当 60 rpm 用**。

1 s 步长下唯一正确的表述：

```
N_enc ∈ {0, 1}，且 P(N_enc = 1) = stepDuration × scanRate / 60
```

**最小修法（3 行）**：把小数部分**跨步进位**，别在步内取整。

```
acc += stepDuration * scanRate / 60.0;
N = (int)floor(acc);
acc -= N;
```

6 rpm 时 10 步攒出 1 次，出现的那一步也对得上。对 360° 扫描，这与"把波束相位当实体状态"
**等价**，不必真去存相位（存相位更通用，能顺带解掉扇区与多目标共享波束的问题）。

## C. 1 s 的接口后果：`detections` 的长度只能是 0 或 1

规格书把 `detections` 交给上层做 M/N。1 s 步长下这个向量只能是 `{}` 或 `{一个元素}`：

- **`max(1, …)` 让空向量永不出现** ⇒ 上层**无法区分"这一步波束没扫到"与"扫到了但没探到"**。
  而 M/N（N 次扫描里有 M 次命中）里的"漏扫"**不是"未命中"**——把两者混为一谈，
  慢转速雷达的航迹建立判据直接失去意义。
- 上层要在**跨步**上做 M/N，就需要一个"第几次扫描"的计数器。规格书说"接触时刻由上层按
  `detections` 序列 + 步长自行分配"，1 s 下这个分配误差最大 1 s（可接受），但**必须写明**：
  计数器只在 `N_enc > 0` 时递增。

## D. 本轮新增发现（9/18 报告未覆盖）

### D-1 表 7.3 与 A.1 `ListStub` 不自洽，且 `ListStub` 本身**不是单调**的

| 偏移/BW | A.1 代码实测 | 表 7.3 | 判定 |
|---|---|---|---|
| 0.0 | +0.00 dB (100 %) | 100 % / 0 dB | OK |
| 0.5 | −3.01 dB (50.0 %) | 50 % / −3 dB | OK |
| 1.0 | **−17.99 dB (1.59 %)** | 5 % / −13 dB | **不符** |
| 1.5 | **−13.73 dB (4.23 %)** | 0.3 % / −25 dB | **不符** |

根因不是数字抄错，而是 **sinc² 方向图不单调**：1.5×BW 已落在**第一副瓣的肩上**，
副瓣峰值 −13.26 dB 出现在 1.61×BW 处，**比 1.0×BW 的 −18 dB 还高**。
⇒ 表 7.3 那张"单调下降"的表**没法靠改数字修好**，必须先声明方向图模型（sinc² / 余弦锥削 / 高斯），
再按模型重算。

副瓣这件事还顺带影响 3c：干扰机从旁瓣进入雷达时，增益不是 0 而是 **−13 dB 量级**，
规格书现在的写法容易让人以为"偏离主瓣就压不进来"。

### D-2 扇区扫描的相遇率差 `360/(B−A)` 倍

规格书三分支里，扇区沿用 `N_scans = step × scanRate / 60`。若 `scanRate` 指
**天线物理角速度**（伺服通常这么给），扇区 `[A, B]` 的相遇率是

```
f_enc = 6 × scanRate / (B − A)      [次/秒]     （全向时 B−A = 360，退化为 rpm/60 ✓）
```

| 扇区跨度 | 与规格书之比 |
|---|---|
| 360° | 1× |
| 180° | 2× |
| 90° | 4× |
| 60° | 6× |

必须把 `scanRate` 的口径写死（转/分 还是 扇区扫/分）。注意
**`pulsesPerDwell = dwellTime × prf` 不受影响**（单次穿越所用时间不变），只有**次数**受影响。

### D-3 没有地平线 / 地球曲率

`altitude` 在 2.2（干扰机）与 2.3（目标）都收了，**没有任何公式用它**。
标准视距 `R ≈ 4.12(√h_r + √h_t) km`：

| 雷达天线高 | 目标高 | 视距上限 |
|---|---|---|
| 20 m | 10 m | 31.5 km |
| 20 m | 100 m | 59.6 km |
| 20 m | 1000 m | 148.7 km |

没有这一段，1 m² 目标在 150 km / 100 m 高度也会被判"探到"——对反舰场景是致命的。

### D-4 收了不用的入参，且没有俯仰维

`seaState`、`surfaceType`（2.4）、目标与干扰机的 `altitude`——四个参数**收了不进任何公式**。
海况对应海杂波，是**低空海面目标的头号限制项**；`surfaceType` 同理。
要么用，要么从入参删掉（现在这样会让人以为已经算了）。

俯仰维同样缺席：只有方位偏离角，没有目标仰角与 `vertBeamWidth` 的比较，
高出垂直覆盖的目标照样会被判"探到"。

### D-5 `falseTargetCount` 把"假回波数"当"假目标数"，`deceptionSlotsUsed` 从不赋值

```
falseTargetCount += P_deception × jammer.prf_hz × stepDuration
```

1 s + prf = 1000 Hz + `P_dec` = 0.9 ⇒ **900 个假目标/秒**。
而一次成功的 RGPO 距离门拖引通常只产生 **1 条假航迹**（多门拖引才有几条）。
`deceptionSlotsUsed` 在 §五 输出表里声明，附录 A.3 参考代码里**从未赋值**，
也没有任何跟踪槽位上限——"900 个假目标"与"消耗 0 个槽位"不可能同时成立。
建议：假目标数按**每次扫描**（或每次跟踪更新）记，并用可用槽位数封顶。

### D-6 `FlushStub` 注释与代码差 60 dB（代码对、注释错）

```
注释：  K = 10·log10((4π/c)²) ≈ −147.55                ← 距离用「米」的口径
代码：  10.0 * std::log10(1.7570265424158548E-09) = −87.552   ← 已含 km→m 的 1e6
```

## E. Swerling 1 的 O(m) 有限项闭式（建议替掉 Kanter 近似）

9/18 给的那条级数要 O(J·N) 项、且必须增量累加。本轮把它化成**只有 m−1 项**的有限和：

```
门限（噪声下统计量 ~ χ²(2m)）：
    Pfa = Q(m, T) = e^{−T/2} · Σ_{k=0}^{m−1} (T/2)^k / k!        先解出 T
    （T 是「统计量」门限；9/18 用的 u = T/2，别混）

Swerling 2（逐脉冲起伏）：
    Pd = Q(m, T/(1+s))

Swerling 1（整段恒定、逐次扫描起伏）：
    q  = m·s / (1 + m·s)
    β  = (1 − q)/2
    Pd = β · q^{−(m−1)} · [ (1/β)·e^{−βT} − 2·Σ_{k=0}^{m−2} q^k · Q(k+1, T) ]
    （m = 1 时求和为空，退化为 e^{−T/(2(1+s))} = Pfa^{1/(1+s)} ✓）
```

**三方互证**：

| 方法 | 结果 |
|---|---|
| O(m) 闭式（本轮） | 见表 7.4 全部 24 格 |
| 蒙特卡洛 30 万次（本轮） | 与闭式差 ≤ 0.0013 |
| O(J·N) 级数（9/18） | 与闭式**逐位一致**（0.121 / 0.466 / 0.578 / 0.486 / 0.782 / 0.839 / 0.791 / 0.925 / 0.946 …） |

**锚点**（Pfa = 1e-6，Swerling 1，每脉冲 SNR）：

| N | Pd = 0.5 | Pd = 0.9 |
|---|---|---|
| 1 | +12.77 dB | +21.14 dB |
| 2 | +10.33 dB | +18.69 dB |
| 10 | +5.19 dB | +13.50 dB |
| 56 | +0.43 dB | +8.71 dB |
| 100 | −1.04 dB | +7.23 dB |

注意 Swerling 1 的**总** SNR 反而**随 N 上升**（Pd = 0.5：12.77 → 18.96 dB）——
这正是"慢起伏目标几乎吃不到非相干积累增益"的教科书特征，**可以拿它当实现对错的判据**：
如果实现出来的 Swerling 1 总 SNR 随 N 下降，说明它算成了 Swerling 2。
